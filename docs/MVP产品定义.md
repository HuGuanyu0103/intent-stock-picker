# MVP定义：自然语言智能选股与策略解释器

> 面向 24 小时黑客松（题目 02）的产品定义 v2。核心判断：**这道题考的不是"选股准不准"，而是"AI 边界设计 + 条件可审计 + 人在回路"**。主链路：模糊语言 → 流式解读 → 带专家值的条件卡（可检查可修改）→ 确定性执行 → 四分组结果与字段级解释 → 结果内追加条件二次收窄 → 保存/回测。

## 一、题目在考什么

| 题目原文 | 真正考的能力 | MVP 落点 |
|---|---|---|
| "模糊语言描述意图" | 模糊语义消歧，不硬翻译 | 解读流声明理解 + 歧义挂卡片原地确认，专家值兜底可直接执行 |
| "可检查、可修改、可执行的数据条件" | 结构化中间表示是产品主角 | 条件卡六要素 + 专家值三档可调；LLM 不直出答案 |
| "冲突识别与条件修改" | 确定性规则拦住/提示 | 硬冲突拦截 + 软权衡提示（引擎真实计数） |
| "AI、筛选引擎、数据工具职责边界" | 第一主角 | 四方职责表 + LLM 输出受 Schema 与指标白名单约束 |
| "为何入选、为何被排除" | 保留逐股逐条件判定痕迹 | pass/fail/unknown 三值 + 结果四分组 |
| "数据口径、时点和缺失条件" | 元数据透明 + 缺失不静默 | 数字带报告期/时点/单位；缺失进隔离组 |
| "条件变化带来什么影响" | 差异化亮点 | 改条件出结果集 diff；结果内追加条件逐轮收窄 |
| "比较、保存、回测或监控" | 筛选不是终点 | P0 比较+保存，P1 轻量回测，监控列边界 |
| "不静默生成正常结论"、不荐股 | 异常与合规 | 失败显式化 + 样例数据模式 + 合规拦截 |

**产品定位**：不是"AI 帮你选股"，而是"AI 把你的模糊想法翻译成你看得懂、改得动、可追溯的条件，机器只负责诚实地算数"。差异化对象是同花顺问财：问财是黑箱查询，本产品是**可检查、可修改、可追溯的条件协作台**。

## 二、目标用户与场景边界

- **用户**：有初步投资想法但说不清量化标准的个人投资者。
- **黄金路径**：输入想法 → 看流式解读（歧义点在卡片上原地确认）→ 检查/微调专家值条件卡 → 运行 → 看入选/差一点/已排除/不可判定 → 在结果内追加条件二次收窄 → 保存 / 回测。
- **非目标**：不做实时行情终端、自动交易、涨跌预测、全 A 覆盖、组合优化、个股诊断分支、多轮语义指代。

## 三、交互时序（含流式解读）

1. 提交后 <500ms 过**意图闸门**：选股意图 / 个股查询 / 预测类 / 闲聊。仅选股意图进流水线；"600519 怎么样"引导回筛选场景；"明天涨不涨"触发合规提示。
2. **SSE 首字 <1–2s**，输出结构化"解读流"（非原始思维链）：逐个意图片段声明"我听到什么 → 我怎么理解 → 落成什么条件 → 置信度/歧义点"，卡片节点随叙事逐个点亮。
3. 解读完成，条件卡完整落地；歧义点不停留在对话反问，而是对应卡片处于黄色"待确认"态，用户在卡上原地点选。
4. **专家值兜底**：所有卡（含待确认卡）默认带推荐专家值，"执行"按钮永远可点，用户不回答任何问题也能跑通。
5. 用户读卡/改条件期间，后台可用草案条件 speculative 预跑一版，但**结果不提前渲染**——叙事是说明书，卡片才是合同，结果只在用户点执行后出现。
6. 执行（热数据秒级）→ 四分组结果；支持追加条件逐轮收窄；保存 / P1 回测。
7. MVP **不做"跳过解读"按钮**；解读流本身保持精简，每句对应一张卡。

**耗时的架构治理（不靠阅读时间掩盖等待）**：服务常驻每日预热沪深 300 全池指标矩阵（盘后定时刷新，演示前手动预热），把分钟级取数与秒级判定分离，执行永远是本地矩阵运算。冷缓存场景给显式进度条（"正在准备 287/300 家公司财务数据"），不转圈。P1 回测需取多期历史数据，做成后台任务 + 完成提示。

## 四、条件对象设计（v2）

### 4.1 条件 JSON

```json
{
  "condition_id": "c_01",
  "quote": "不要 ST",
  "intent_group": "g_risk",
  "metric": "is_st",
  "metric_type": "boolean",
  "operator": "==",
  "value": false,
  "params": {},
  "polarity": "exclude",
  "risk_level": "hard",
  "on_unknown": "quarantine",
  "period": "最新交易日",
  "caliber": "股票名称含 ST/*ST 或存在其他风险警示",
  "as_of": "2026-09-22 收盘",
  "preset_tier": "strict",
  "source": "expert_default",
  "confidence": 0.95,
  "needs_confirm": false
}
```

字段要点：
- `metric_type`：`numeric`（数值比较）/ `boolean`（ST、停牌等）/ `enum_set`（行业、概念 in / not-in）。
- `polarity`：`include`（正向画像）/ `exclude`（反向排除，红线清单）。
- `risk_level`：`hard`（一票否决）/ `soft`（偏好性）。
- `on_unknown`：`quarantine`（隔离待核实）/ `ignore`（不影响入选，仅标注）。
- `preset_tier`：宽松 / 适中 / 严格三档专家值，默认中档。
- `source`：`expert_default`（专家值，灰）→ `user_adjusted`（用户调过，蓝）。
- `intent_group`：一对多映射时（"走势稳定"→波动率+回撤两张卡）同组卡片联动高亮、联动删除提示。
- LLM 全部产出受 Schema（pydantic）约束；`metric` 只能取自指标注册表白名单，表外指标/类型不匹配/报告期不存在，解析层拒绝并降级为"未理解"灰卡。

### 4.2 正向画像与反向排除

用户心智是"理想画像 + 红线清单"两层，条件卡 UI 分两区：**我想要的**（蓝）/ **我不要的**（红，红线图标），卡上带 polarity 开关可一键翻转。

LLM 专门识别排除表达：剔除/排除/不要/避开/除了…都/没有…风险；注意隐性否定（"没有退市风险的"句式正向、语义排除）与集合排除（"除了银行都可以"→ 行业 not-in 谓词）。评测集含刁难怪问"低估值的不要"（疑似口误，触发澄清而非默默执行）。

排除卡试算显示"将剔除 N 只：ST 7 只、房地产 21 只"。触发硬排除的股票**不进 near-miss**，不用"就差一点"诱导用户碰自己划的红线。

### 4.3 排除项查无数据策略（已拍板）

| 排除项性质 | 查到有 | 查到无 | **查不到（unknown）** |
|---|---|---|---|
| 硬红线（ST、立案、大额减持等） | 剔除 | 保留 | 进"风险待核实"隔离组 + 提供"无法核实即剔除"从严开关 |
| 软偏好（不想要高波动等） | 剔除 | 保留 | 不影响入选，股票卡标注"该项无数据" |

README 明示这是产品立场：不替用户做"疑罪从有/从无"的判断。

### 4.4 结果四分组

| 分组 | 判定 | 呈现 |
|---|---|---|
| 入选 | include 全 pass，未触发 exclude | 逐条件证据，按贴合度排序 |
| 差一点 | 仅 1 条 include fail，未触发排除 | 卡点字段与差距（"PE 分位 52%，阈值 50%"） |
| 已排除 | 触发任一 exclude | **默认折叠只给计数**，可展开明细，红线样式 |
| 不可判定 | 含 unknown | 拆两小类：数据不足 / 风险待核实（带从严开关） |

### 4.5 三值逻辑

pass / fail / unknown：字段缺失、未披露、接口失败一律 unknown，永不混入入选或淘汰。

## 五、意图 → 条件的转化管线

```
原文 → ①意图闸门 → ②切片（带 quote）→ ③指标接地（白名单检索+LLM选择）
     → ④四分流：确定→成卡 / 模糊→解读流声明+待确认卡 / 未理解→灰卡手动指定 / 非筛选意图→引导或合规拦截
     → ⑤专家值填充 → ⑥用户确认/微调 → ⑦编译谓词执行
```

**模糊词翻译词典（产品预设口径，非 LLM 临场发挥；换模型行为不变）：**

| 模糊词 | 专家默认翻译（中档） | 澄清备选项 |
|---|---|---|
| 经营改善 | 归母净利润同比 > 0 且本期增速 ≥ 上期 | 营收口径 / 单季口径 |
| 估值合理 | PE-TTM 为正且低于同行业中位数（行业内分位 ≤50%） | 自身历史分位(P1) / PB |
| 走势相对稳定 | 近 60 日年化波动率池内最低 40% + 120 日回撤 ≤ 15% | 基准：大盘/行业/自身 |
| 便宜 | 估值分位低（**禁止映射为绝对股价低**，评测锁死） | PE/PB/股息率 |
| 活跃 | 近 20 日日均成交额 > X | — |
| 只看新能源 / 剔除银行 | 概念/行业 enum_set 的 in / not-in | 多概念候选时待确认 |
| 龙头 | 无法无争议量化 → 未理解灰卡 | 引导改成市值/市占率口径 |

已拍板规则：
- **时间词固化**："最近"= 最新已披露定期报告；趋势改善 = 近 2 期；长周期 = 近 1 年。词典写死，LLM 不临场解释。
- **行业/概念集合条件 P0 支持**（enum_set + 同花顺概念映射，多候选走待确认卡）。
- **多轮指代不做**："把最后一个放宽点"引导用户直接点卡片；但"在结果里再加 XX"的追加意图完整支持。

## 六、专家值设计

每张条件卡默认落专家值，配齐三件套：

1. **数值 + 三档预设**：宽松 / 适中（默认）/ 严格。例：PE 行业内分位 70% / 50% / 30%。档位显示语义说明（"严格：比同行业 70% 的公司都便宜"）。
2. **一句话理由**：为什么这么定，可摆上卡片、写进 README；注明"产品预设口径，可自行调整，不构成投资建议"。
3. **来源标记**：专家值（灰）/ 已调整（蓝），永远可辨。

阈值修改用数字框/滑块/口径下拉；改后卡面试算计数即时更新，点"重新筛选"才跑全量并出 diff（编辑与执行分离）。

## 七、筛选引擎

### 7.1 样本池

沪深 300 成分股（P1 扩至 +中证 500）；默认开关剔除 ST/*ST、上市不满 1 年、当日停牌（可关）。边界写入 README。

### 7.2 预注册指标白名单（16 个，三类）

数据全部映射已核实可用的扶摇接口：valuations / financial-indicators / income statements / prices snapshot+historical / ths-index-membership / corporate-actions / calendar。

| 分组 | 指标 | 口径 |
|---|---|---|
| 经营改善 | 归母净利润同比、营收同比、增速边际改善、ROE(TTM)、毛利率同比变动 | 最新定期报告，趋势看近 2 期 |
| 估值合理 | **PE-TTM 行业内分位（默认，横截面快照口径）**、PB 行业分位；自身历史分位 P1（季频近似） | 亏损/负 PE 记 unknown |
| 走势稳定 | 年化波动率（60日√242）、最大回撤（120日）、相对沪深300 Beta（120日周回归）、MA60 乖离绝对值 | 后复权价 |
| 流动性 | 日均成交额（20日） | 历史K线成交额均值 |
| 规模 | 总市值 ≈ PB(MRQ) × 净资产(MRQ) | 扶摇无股本字段，近似口径写入 README |
| 交易过滤 | ST（名称含 ST/*ST）、新股（list_date 不满 1 年）、停牌（当日快照缺行） | 默认开 |

**扶摇接口实测结论（2026-09-23，真实 Key 验证通过）：**
- 鉴权 `X-api-key` 头；限流 5 req/s（超限 code=4001）；沪深 300 成分 `000300.SH` 实测返回 300 只。
- 估值接口**仅最新快照**（pe_ttm/pe_mrq/pb_mrq/ps_ttm/pcf_ttm，100 只/次），明确不提供历史序列 → 历史分位不能直取；故"估值合理"专家口径改为**行业内横截面分位**（只需快照、零额外取数、口径干净），自身历史分位降 P1（季频 TTM 盈利 + 后复权价近似，标注口径）。
- 财务指标真实字段名与文档有出入：归母净利同比 = `calculate_parent_holder_net_profit_yoy_growth_ratio`、营收同比 = `calculate_operating_income_yoy_growth_ratio`、ROE = `index_weighted_avg_roe`；按"单股×单报告期"取数，边际改善对比 2026-2 与 2025 年报两期累计同比，口径写死。
- 无股本/流通股本/流通市值字段；总市值用 PB×净资产近似；流动性只保留日均成交额，删掉流通市值与换手率。
- 行业归属：同花顺行业指数实测 320 个（多级），每日预热反向构建 股票→行业指数 映射，取成员数最少的行业作为同业组；组内不足 5 只回退全池分位。
- 概念集合条件：cn_concept 目录 + 成分股接口已验证可行（"新能源"类表达）。
- 全池预热实测估算：快照类 6 次 + 财务指标 300×2 期≈600 次（≥2 分钟）+ 120 日K线 300 次（≥1 分钟）+ 行业映射 320 次（≥1 分钟），每日约 4–5 分钟；执行仍是本地矩阵秒级。

### 7.3 冲突识别

- **硬冲突（阻止运行）**：同指标阈值区间无交集、时间矛盾、白名单外指标、互斥开关。定位到具体两张卡。
- **软权衡（提示可执行）**：低估值+高成长等风格张力，引擎用全池真实计数给"预计命中 0–3 只"，不由 LLM 估。

### 7.4 条件试算

每张卡显示池内满足计数（"187/300 满足此条"），卡片区顶部显示交集预估；预计命中 >50 只提示"条件偏宽松"。计数全部引擎实时计算。

## 八、结果呈现与二次筛选（用户确认之后）

1. **入选列表按"与你条件的贴合度"排序**：引擎对每条条件算标准化余量（实际值距阈值的远近），默认按"最短板"聚合（所有条件都稳稳满足的排前，任一擦线的沉底），可切换按单指标/市值排序。每条余量透明可见；文案明示"越靠前 = 越贴合你设的标准，不代表越好"，不做黑箱综合分、不做个性化推荐。
2. **行业 facet 导航**：左侧行业分布（电子 18、医药 12…），点击即收窄——本质自动追加一张"行业 ∈ X"条件卡，复用条件模型与 diff，可在卡片区删除。
3. **结果内追加条件（二次筛选主形态，P0）**：结果页输入框支持"在当前结果里，再要求市值 200 亿以上、剔除次新股"，走同一解析管线追加卡片，结果集 diff 高亮，每轮可见"78 只 → 23 只，由哪张卡驱动"。支持无限轮收窄。
4. **P1：AI 收紧建议**——结果过多时给 2–3 个带预估数量的调法（"波动率收到最低 25% → 约 23 只"），一键应用。
5. **比较视图（P0）**：勾选 2–4 只，条件指标横向对比表。

页面结构：左对话区（解读流）/ 中条件卡两区（想要/不要）/ 右结果四页签；hover 数字显示字段名、口径、报告期/时点、单位、来源接口；事实（黑）/ AI 理解（蓝标）/ 不确定（黄）三色体系。

## 九、四方职责边界

| 角色 | 只允许做 | 不做 |
|---|---|---|
| LLM | 意图解析、受 Schema 约束的条件 JSON、解读流叙事、澄清选项、解释文案 | 不取数、不算指标、不决定入选、不输出 JSON 外数字、不用白名单外指标 |
| 确定性引擎 | 条件校验、指标计算、三值判定、冲突、排除归因、贴合度、试算计数、diff、回测统计 | 不产生自然语言结论 |
| 数据工具（扶摇/iFinD） | 提供带时点与单位的原始字段 | — |
| 人 | 确认/改条件、回答（可不答）、决定执行保存 | — |

LLM 文案中每个数字来自引擎判定结果对象，前端模板渲染，禁止编数（沿用观澜"无数据不输出"）。

## 十、合规与异常

- 措辞红线：不出现买入/卖出/目标价/必涨/推荐；"入选"表述为"符合你设定的条件"；专家值与回测均带"不构成投资建议"；末道合规词表校验（复用观澜 guardrails）。
- 异常矩阵：单接口超时（重试 2 次→该指标全池 unknown + 状态条）、Key 缺失（自动进样例模式，全程横幅）、字段全池缺失（禁用对应指标卡）、非交易日（显示最近交易日时点）。样例数据与真实数据全程显著区分。

## 十一、技术架构与复用

- 后端单服务（Flask/FastAPI）：`fuyao_client`（5 req/s 限速、重试、SQLite/Parquet 当日缓存、fixture 降级、每日预热）、`metrics`（16 指标 pandas 矩阵）、`engine`（条件编译、三值四分组、冲突、试算、贴合度、diff）、`llm`（SSE 解读流、意图→JSON、白名单校验、文案，DeepSeek）、`store`（方案/运行记录）、`backtest`（月度等权，P1）。
- 前端：单页 HTML + ECharts（延续观澜栈）：SSE 解读流、条件卡两区、四页签、facet、diff、回测曲线。
- 复用观澜：退避重试/熔断器、guardrails、Eval 组织方式、layer3_backtest 日历与收益计算、README 参数手册风格。
- 部署：渲染主机 + Pages；Key 走环境变量，仓库仅 `.env.example`；无 Key 自动样例模式，URL 永远可点开。

## 十二、3 分钟演示脚本

1. 输入"经营改善、估值合理、走势相对稳定，不要 ST 和上市不满一年的"。
2. 解读流逐句播放：正向三要求 + 两条排除红线；"估值合理"卡停在黄色待确认，原地点选"对标自身近三年"。
3. 卡片落地：专家值三档，把波动率中档切到严格档，试算交集实时从 23 变 11。
4. 执行：入选按贴合度排序，展开一只看逐条件证据；"差一点"看某股卡在 PE 分位 52%；"已排除"折叠计数展开看 ST 7 只；"不可判定"看风险待核实组与从严开关。
5. 结果内追加"市值 200 亿以上"→ diff：78 → 31 只；再点行业 facet 收窄。
6. 保存方案 → P1 一键回测近一年 vs 沪深 300，底部风险提示。
7. 备用彩蛋：断数据源，展示状态条与样例模式。

## 十四、测试与验证记录

- 主链路：3 标准短语 + 5 边界表达（白名单外词、互相打架条件、纯闲聊、个股查询、预测诱导）。
- 排除专项 5–6 例：显性否定、隐性否定（"没有退市风险的"）、集合排除（"除了银行"）、口误（"低估值的不要"）、硬红线字段缺失。
- 解析评测集 15–20 条意图→期望条件 JSON：接地准确率、澄清触发率、未理解召回率；锁死"便宜→低股价"错误；记录 AI 初版错误与人工修正。
- 异常：接口 500/超时、Key 缺失、财报未披露、非交易日、空结果。
- 合规：荐股措辞诱导 10 例断言拦截率。

## 十五、已知边界（README）

样本池仅沪深 300（P1 扩 800）；指标仅 16 个预注册口径；条件仅 AND 组合 + 单指标谓词（含 in/not-in），不支持 OR、嵌套、跨期表达式；不含资金面/消息面条件；不支持多轮语义指代；回测为简化等权月度调仓（费用滑点处理情况单列）；无个性化推荐与涨跌预测；样例与真实数据全程区分。
